### 2. Content-Type Serialization Fix

#### **src/vasttams/segments/service.py**
**Problem**: `content-type` field in `put_url` was serializing as `None`  
**Root Cause**: Pydantic alias handling - `HttpRequest(content_type=value)` doesn't work with aliases

**Fix**: Use `model_validate()` with dict using alias key
```python
# Before
put_url=HttpRequest(
    url=presigned_url,
    content_type=content_type,
    headers={}
)

# After
put_url_data = {
    "url": presigned_url,
    "content-type": content_type,  # Using alias key
    "headers": {}
}
put_url=HttpRequest.model_validate(put_url_data)
```

#### **src/vasttams/common/storage/main_service.py**
- Applied same fix for consistency
- Both storage allocation paths now correctly serialize `content-type`

**Result**: ✅ `test_storage_allocation_with_content_type` now passes

## 🔍 Technical Details

### Pydantic Alias Handling
When using aliases in Pydantic models, you must use `model_validate()` with a dict:
```python
class HttpRequest(BaseModel):
    content_type: Optional[str] = Field(None, alias="content-type")

# ❌ Doesn't work
HttpRequest(content_type="video/mp2t")

# ✅ Works
HttpRequest.model_validate({"content-type": "video/mp2t"})
```

### Credential Validation Pattern
Always validate credentials are non-empty strings before use:
```python
has_valid_credentials = (
    access_key and secret_key and 
    isinstance(access_key, str) and isinstance(secret_key, str) and
    access_key.strip() and secret_key.strip()
)
```

### Video Discovery Pattern
Use `discover_video_files()` to automatically find and process videos:
```python
videos = discover_video_files(Path('test_videos'))
for video_info in videos:
    metadata = video_info['metadata']  # Already extracted via ffprobe
    # Use metadata for flow creation, etc.
```
