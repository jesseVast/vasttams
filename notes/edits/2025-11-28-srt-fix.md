# Code Changes - November 28, 2025 (SRT Stream Ingestor Fix)

## Problem
Stream ingestor with SRT creates only one segment and then exits, but cannot create new segment files.

## Root Cause
FFmpeg was exiting after creating the first segment when processing SRT streams. This happened because:
1. SRT streams may have temporary connection issues that cause FFmpeg to think the stream has ended
2. FFmpeg's segment muxer exits when it encounters EOF or connection errors
3. No reconnection options were configured for SRT streams

## Solution
Added SRT-specific input and output options to keep the connection alive and prevent premature exit:

### Input Options (for SRT streams)
- `reconnect: '1'` - Enable automatic reconnection
- `reconnect_at_eof: '1'` - Reconnect even if stream seems to end
- `reconnect_streamed: '1'` - Reconnect for streamed inputs
- `reconnect_delay_max: '2'` - Maximum delay between reconnection attempts (2 seconds)

### Output Options (for all live streams)
- `fflags: '+genpts'` - Generate presentation timestamps
- `avoid_negative_ts: 'make_zero'` - Handle timestamp issues that could cause FFmpeg to exit

## Files Modified
- `apps/stream_ingestor/stream_ingestor/stream_processor.py`
  - Added SRT stream detection (line 203)
  - Added SRT-specific input options when SRT stream is detected (lines 210-216)
  - Pass input_options to VideoSource constructor (line 220)
  - Added output options to prevent premature exit (lines 93-99)

## Testing Notes
- SRT streams should now continue creating segments instead of exiting after the first one
- Reconnection options ensure FFmpeg keeps trying even if there are temporary connection issues
- Output options prevent FFmpeg from exiting on timestamp or other minor errors
