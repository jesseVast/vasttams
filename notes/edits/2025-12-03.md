# Code Changes - December 3, 2025

## Vector Dimension Mismatch Issue and Logging Improvements

### Problem
- Error: "Vector must be exactly 1536 dimensions (configured for model 'text-embedding-ada-002'), got 768 dimensions"
- Error from vastdbmanager: "Length of item not correct: expected 1536 but got array of size 768"
- Config file has `model_dimension: 768` for `nomic-embed-text:latest`, but system expects 1536
- Embedder initialization status not visible in logs

### Root Cause
1. **Config Loading**: Config file may not be loading properly, causing system to use defaults (1536 for text-embedding-ada-002)
2. **Table Schema Mismatch**: The `vectors` table was created with 1536 dimensions (from previous config or default), but current config requires 768 dimensions
3. **Lack of Visibility**: No INFO-level logging to show:
   - Whether config file was loaded
   - What embedding settings are actually being used
   - Whether embedder initialized successfully

### Solution

#### 1. Added INFO-Level Logging for Config Loading
- Changed config file loading log from DEBUG to INFO level
- Added confirmation message when config loads successfully
- Added detailed logging of embedding configuration (provider, model, dimension, endpoint)

**Files Modified:**
- `src/server/vasttamsserver/core/config.py`
  - Line 334: Changed `logger.debug()` to `logger.info()` for config file loading
  - Lines 594-608: Added INFO-level messages for successful config load and embedding configuration details

#### 2. Added INFO-Level Logging for Embedder Initialization
- Added logging at start of embedder initialization showing all settings
- Added logging when embedder initialization fails
- Added final status logging showing whether embedder was successfully initialized

**Files Modified:**
- `src/server/vasttamsserver/vast/embedding_service.py`
  - Lines 47-53: Added INFO-level logging at start of initialization with all settings
  - Line 110: Added INFO-level message when initialization fails
  - Lines 126-130: Added final status logging

#### 3. Added Embedder Initialization at Server Startup
- Initialize embedding service during server startup to ensure config is loaded
- Provides early visibility into embedder initialization status
- Helps debug dimension mismatch issues by showing config values at startup

**Files Modified:**
- `src/server/vasttamsserver/main.py`
  - Lines 126-135: Added embedding service initialization in lifespan startup handler

### Known Issue: Table Schema Mismatch

If you see dimension mismatch errors, the `vectors` table was likely created with a different dimension than your current config. The table schema is fixed at creation time.

**To Fix:**
1. **Option A**: Drop the `vectors` table and restart the server (it will recreate with correct dimension)
2. **Option B**: Update `config.yaml` to match the existing table dimension:
   ```yaml
   embedding:
     model_dimension: 1536  # Match existing table
   ```
