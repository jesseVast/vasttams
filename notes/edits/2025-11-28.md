# Code Changes - November 28, 2025

## HLS Individual Playback Fix

### Problem
- Individual play button not working when autoplay is off
- Autoplay on: all videos play and stop, then individual play works
- Autoplay off: no video would play even though first frame loaded

### Root Cause
When `play()` was called on mpegts player with autoplay off:
1. `play()` promise resolved successfully
2. But `readyState` immediately dropped to 0
3. `MediaSource onSourceEnded` event fired
4. Player reinitialized (onReady called again)
5. Video stayed paused, no PLAY/PLAYING events fired

The mpegts player's MediaSource was ending when play() was called, causing the player to reset.

### Solution
- Added detection for `readyState` drop after `play()` resolves
- Wait for player to reinitialize (listen for `canplay` and `playing` events)
- Retry `play()` once player is ready again
- Added comprehensive logging to track playback state transitions

### Files Modified
- `ui/src/components/VideoPlayer.tsx`
  - Enhanced `play()` method to detect and handle player reinitialization
  - Added event listeners for `play`, `playing`, `waiting`, `stalled`, `canplay`, `canplaythrough`
  - Added detailed logging for debugging playback issues
  - Improved promise handling with state checks after resolution

- `ui/src/components/SegmentMediaWidget.tsx`
  - Enhanced `onReady` callback logging
  - Improved `onPlay` handler logging with detailed state information
  - Better error handling and state reporting

## VideoControlsWidget Visibility Fix

### Problem
- Info box (VideoControlsWidget) missing below video player in scrollview
- Widget was rendered but not visible

### Root Cause
VideoControlsWidget was inside a Box with fixed `height`, causing it to be cut off or hidden.

### Solution
- Moved VideoControlsWidget outside the fixed-height Box container
- Applied fix to both rendering paths:
  - Direct segment URL (mpegts.js) path
  - HLS fallback path
- Native player path already had correct structure

### Files Modified
